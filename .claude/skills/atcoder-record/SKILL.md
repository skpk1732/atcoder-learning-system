# AtCoder 精進記録の作成

ユーザーがAtCoderで解いた／苦戦した問題の「精進記録ノート」を、テンプレートに沿って作成するスキル。

## 🔴 絶対に忘れない運用ルール（ユーザーの明示要望・2026-07-19）

ユーザーが問題を解いた／コンテストに参加したと報告したら、**言われなくても必ず**以下をやる：
1. **精進記録を残す**（解けた問題も、詰まった問題も、本番回も。1問1ファイル）
2. **実測Diffを取得**して記録の `Diff` に入れる: `python 2_Areas/AtCoder/tools/fetch_submission.py --diff <problem_id>`（未算出なら空でよいが、後日必ず埋める）
3. **コンテスト参加回なら新レートを取得**: `python 2_Areas/AtCoder/tools/fetch_submission.py --rating` → `レート目標と現状.md` のレート推移ログに追記
これらは「やり忘れが多い」とユーザーから指摘済み。記録作成のたびにこの3点を確認する。

## 入力

ユーザーは引数として問題の識別子を渡せる（例: `ABC401_C`、`abc401_c`、問題URL、問題名）。
引数が無い／曖昧な場合は、以下を1つだけ短く質問して確定する:
- 「どの問題ですか?（例: ABC401_C、またはURL）」

## 手順

1. **テンプレートを確認**: `2_Areas/AtCoder/精進記録Template.md` を読み、最新の項目構成に合わせる（テンプレートが更新されている可能性があるため毎回読む）。テンプレートが存在しない場合は、本スキル記載の構成（フロントマター＋問題リンク/概要/考察/つまずき/学び/コード/振り返り）で代替する。

2. **問題情報を整理**:
   - 問題ID（例: `ABC401_C`）とコンテスト名（例: `ABC401`）を引数から抽出。
   - URLが与えられたらそのまま「問題リンク」に使う。IDだけなら **小文字に正規化して** `https://atcoder.jp/contests/abc401/tasks/abc401_c` の形を推測して記載（AtCoderのURLは小文字。不確実なら確認）。
   - 注意: 古いABC（〜ABC126あたり）のC/D問題は problem_id が `arc086_a` のようにARC側になっていることがある（ABC081_C = arc086_a 等）。リンク切れに気づいたら疑う。

3. **ユーザーに最小限ヒアリング**（一度にまとめて聞く。すでに会話で分かっていれば省略）:
   - 結果は? （AC自力 / 解説AC / 未AC）
   - [[C問題突破ガイド]] の①〜⑦のどのパターンだった?（①全探索 ②数学・規則性 ③文字列 ④累積和 ⑤ソート貪欲 ⑥map/set ⑦シミュレーション。分からなければ空でOK）
   - つまずいた点 と 学び（1行）。←ここが最重要。「特になし」なら省略可。

4. **ファイル作成**: `2_Areas/AtCoder/精進記録/<問題ID> <問題名>.md` を作成。
   - ファイル名例: `ABC401_C 問題名.md`（問題名が不明なら `ABC401_C.md`）。
   - フロントマターの `日付` は会話コンテキストの現在日付を使う（`{{date}}` のままにしない）。
   - `tags: [精進, AtCoder]` を必ず付ける（MOCのDataview集計のため）。**フロントマター内のタグに `#` を付けない**（`#` はYAMLではコメント開始記号で構文が壊れる。本文中で使うときだけ `#精進` と書く）。
   - **集計用の正規化キーを必ず入れる**（自由記述の `テーマ`/`結果` はニュアンス保存用。集計はこちらを使う）:
     - `結果区分:` … `自力AC` / `解説AC` / `未AC` のいずれか
     - `型:` … `全探索` / `累積和` / `二分探索` / `DP` / `グラフ` / `数学` / `貪欲` / `データ構造` / `文字列` / `数え上げ` / `インタラクティブ` / `その他` から主たる1つ
   - フロントマターに `problem_id: <AtCoder上のID>` を入れる（例: `problem_id: abc129_c`。**古いABCのC/DはARC側のIDのことがある**——ABC081_C は arc086_a。ツールの `--diff` や提出取得との自動対応付けに使う）。
   - フロントマターの値に `: `（コロン＋空白）を含むときは必ずクォートで囲む（YAML破損防止）。
   - テンプレートの各セクションを、ヒアリング結果で埋められる範囲で埋める。コードは分かれば要点だけ、なければ空でよい。

5. **完了報告**: 作成したファイルパスを伝え、「`学び` だけは後で必ず埋めるように」と一言添える。`#精進` タグにより [[AtCoder MOC]] のDataviewに自動で並ぶことも伝える。

## 方針

- **速さ優先**。完璧に全項目を埋めさせない。最低限「問題ID・テーマ・学び1行」が入ればよい。
- 解けた問題でも記録は可能だが、価値が高いのは「解けなかった／苦戦した問題」。サクッと解けた問題なら「記録しなくてもいい」と伝えてよい。
- ユーザーはPython（PyPy）ユーザー。コード例を扱うならPythonで。
- 既存の同名ファイルがあれば上書きせず、追記するか確認する。
