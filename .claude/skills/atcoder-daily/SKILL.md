# 今日の1問（AtCoder 練習問題の提案）

ユーザーの現在のレベルに合った練習問題を提案するスキル。解法は明かさず、「何を・なぜ解くか」を示して背中を押す。

## 手順

1. **現在地を把握**:
   - `2_Areas/AtCoder/レート目標と現状.md` を読み、現在レート・到達度・苦手分野を確認する。
   - `2_Areas/AtCoder/精進記録/` フォルダの中身（ファイル名）を見て、最近どのテーマ・難易度を解いたかを確認する。
   - **重複回避**: `python 2_Areas/AtCoder/tools/fetch_submission.py --list --ac` で**AC済み問題IDの全履歴**を取得し、提案候補から除外する（精進記録に無い昔のACも拾える。API未反映の直近数十分は漏れる点は許容）。
   - （2026-06時点の既定: レート約70、A・B安定・Cで苦戦、Python/PyPy。最新は上記ファイルで上書きする）

2. **難易度の狙いを決める**（2026-07-05〜 ハイブリッド期）:
   - **主軸**: 計測付きC演習——ABCのC問題 **Diff 400〜600** を「初見・15分・自力AC」目標で（タイマー計測を促す）。
   - **並行**: Phase 2の新規インプット——**BFS/DFS・Union-Find のやさしい問題**（Diff 〜600）や、やさしめのD問題を1問混ぜてよい（新しい型のときはその旨だけ伝え、テーマ名は伏せる方針を維持）。
   - 精進記録から明らかに特定テーマが苦手なら、そのテーマを優先する。
   - 15分自力ACが安定したらPhase 2（D中心）へ全面移行（`緑水 最短ロードマップ.md` 参照）。

3. **問題を選ぶ**:
   - 候補を決めたら **必ず実測Difficultyを照会**: `python 2_Areas/AtCoder/tools/fetch_submission.py --diff <problem_id> ...`（AtCoder Problems準拠・7日キャッシュ）。**記憶による推定Diffをそのまま提示しない**（±200以上ズレた実績あり）。狙いの帯から外れていたら問題を選び直す。
   - 注意: 古いコンテスト（ABC126以前など）のDiffは参加者層の違いで**高めに出る**傾向。数値と体感のズレを頭に入れておく。
   - WebSearch / WebFetch が使えるなら [AtCoder Problems](https://kenkoooo.com/atcoder/) や問題ページも参照してよい。

4. **提案フォーマット**（1〜3問。各問について）:
   - 問題名・コンテスト・問題URL
   - 推定Difficulty
   - **テーマ（①〜⑦のどれか）は伏せる**。ユーザー自身に「どの型か」を考えさせるのが狙いなので、解法カテゴリを明かさない。
   - **解法・考える観点のヒントも書かない**。問題URLと難易度だけを渡し、考察はユーザーに委ねる。
   - 内部的にはテーマ・レベルでバランスを取って選ぶが、その意図は出力に書かない。

5. **締め**:
   - 「まず制約とサンプルを自分で読み、どの型か見極めてから解く」よう促す。
   - 「15〜20分考えて解けなければ解説を見て、翌日upsolve」を促す。
   - 解いたら `/atcoder-record`（atcoder-record スキル）で精進記録をつけるよう案内する（テーマは記録時に振り返る）。

## 方針

- 必ず**今のレベルに合わせる**。レートが上がっていれば難易度帯も上げる（緑が見えたらDや典型90問★4も混ぜる）。
- **テーマ・解法・ヒントは伏せる**（ユーザー要望）。提案は「問題名・URL・推定Difficulty」まで。型を見抜く練習を妨げない。
- ネタバレ厳禁。答えに踏み込まない。
- ユーザーはPython（PyPy）ユーザー。
